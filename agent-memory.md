# Agent Memory

- harness/run.js: shapeValue is mode-driven and should validate/normalize only, not fabricate payloads.
- script-item/webhook in harness accept object input or stringified JSON; plain strings are passed through only when parse fails.
- preprocessor in harness returns params.value when present, otherwise returns params as-is.
- script.js example now accepts object or JSON-string input; it remains a script-item oriented example payload (url, expectedStatusCode, searchText).
- If adapting script.js for preprocessor or webhook, adjust expected input/output contract explicitly in that script.
- script.zabbix.js is auto-generated by `npm run build:zabbix` — never edit it directly; changes belong in script.js.
- params.json structure is developer-defined per project; the example structure (url, expectedStatusCode, searchText) is not a contract.
- todo.md is the agent-developer handoff file: developer writes their plan there, agent appends handoff points that require manual developer action to unblock progress.

# Agent instructions baseline

- All agents should read `README.md` and `agent-memory.md` (this file)
- Help developer utilize the tasks and debug options if in vscode
- script.js (the main script) must be Zabbix Duktape and ES5 compatible
- there is a vscode task available to lint script.js
- `npm run lint` is also available to perform a quick lint to assure zabbix compatibility
- if the developer writes ES6 (or later) JS, help them correct this with suggestions
- help the developer save tokens
  - no glazing, do not assume personality, simplify language, be brutally honest, use text decorations sparingly
  - abbreviate, but keep technical terms intact
- update `agent-memory.md` with any new decisions, patterns, or constraints discovered during the session
